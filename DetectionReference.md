## 1. Windows Security Event ID Reference

These are the core Event IDs for SOC detection work in a Windows Active Directory environment. Each entry includes what the event means, why it matters for detection, and key fields to examine.


| Event ID | Event Name | Detection Value | Key Fields and Notes |
|---|---|---|---|
| 4624 | Successful logon | Baseline event — correlate Logon_Type with source to identify suspicious authentication patterns | Logon_Type (2=interactive, 3=network, 10=RDP), Account_Name, Source_Network_Address |
| 4625 | Failed logon | Brute force detection — alert on 5+ failures within 60 seconds from the same source | Sub_Status: 0xC0000064=username not found (enumeration), 0xC000006A=wrong password (credential attack) |
| 4648 | Logon with explicit credentials | Lateral movement and pass-the-hash indicator — rarely seen in legitimate interactive sessions | Usually generated by scripts, tools, or attack frameworks rather than human logins |
| 4672 | Special privileges assigned to new logon | Admin logon indicator — tracks who is receiving elevated access | Pair with 4624 to confirm administrative activity on sensitive systems |
| 4688 | Process created | Execution detection — catches malicious child processes and command line abuse | Requires audit process creation policy or Sysmon. Fields: New_Process_Name, Creator_Process_Name, Process_Command_Line |
| 4698 | Scheduled task created | Persistence mechanism detection — attackers commonly use scheduled tasks for persistent execution | Requires "Audit Other Object Access Events" enabled via GPO. Fields: Task_Name, Account_Name |
| 4720 | User account created | Backdoor account detection — new accounts created outside normal provisioning windows are suspicious | Account_Name is a multivalue field — use mvindex(Account_Name,1) for the created account name |
| 4726 | User account deleted | Attacker cleanup indicator — rapid create and delete sequence (4720 followed by 4726) is a red flag | Pair with 4720 to see full account lifecycle |
| 4732 | Member added to security-enabled local group | Privilege escalation indicator — most significant when the target group is Administrators | Member_Name may be blank if SID is not resolved. Use SAM_Account_Name from correlated 4720 event instead |
| 4768 | Kerberos TGT requested | Authentication baseline — look for unusual accounts, off-hours requests, or unknown source IPs | Normal domain authentication generates this event. Anomalies stand out against a clean baseline |
| 4769 | Kerberos service ticket requested | Kerberoasting detection — the primary detection event for this attack technique | Ticket_Encryption_Type=0x17 indicates RC4, which is weak and specifically requested by attack tools. AES (0x12/0x18) is normal |
| 4771 | Kerberos pre-authentication failed | Failed Kerberos auth — possible password spray against domain accounts | Similar to 4625 but specific to Kerberos authentication path |
| 4776 | NTLM authentication attempt | Pass-the-hash detection when combined with lateral movement indicators | Watch for unusual source machines or accounts authenticating via NTLM where Kerberos would be expected |
| 7045 | New service installed | Persistence and privilege escalation detection — services are an alternate persistence mechanism | Fields: Service_Name, Service_File_Name, Service_Account. Unusual service paths or names warrant investigation |

## 2. Logon Type Reference

Logon_Type is one of the most important fields in EventCode 4624 and 4625. Understanding what each type means lets you immediately assess whether a logon event is suspicious.

| Type | Name | How Authentication Happened | Primary Threat Signal |
|---|---|---|---|
| 2 | Interactive | Physical keyboard at the console | Unusual on servers — flag logons at odd hours or from unexpected accounts |
| 3 | Network | Over the network via SMB or shares | Key lateral movement indicator — an account authenticating to multiple machines via Type 3 is suspicious |
| 5 | Service | Service account authenticating at startup | Pair with EventCode 7045 — a new unknown service account using Type 5 warrants investigation |
| 7 | Unlock | Lock screen unlocked | Mostly noise — worth flagging only if failures occur at unusual hours |
| 10 | Remote Interactive | RDP session | High value event — always investigate the source IP and whether the account normally uses RDP |

## 3. Sysmon Event ID Reference

Sysmon provides telemetry that Windows Security events alone cannot. These events require Sysmon to be installed and configured on the endpoint with an appropriate configuration file.

| EventCode | What It Captures | Detection Use Case | Key Fields |
|---|---|---|---|
| 1 | Process created | Primary hunting event for any execution. Captures full command line, parent process, and file hashes — far richer than EventCode 4688 | Image, ParentImage, CommandLine, Hashes, User |
| 3 | Network connection | What did a process connect to after executing — useful for C2 beaconing detection | Image, DestinationIp, DestinationPort, DestinationHostname |
| 7 | Image loaded (DLL) | Advanced — detects DLL injection by tracking which libraries a process loads | Image, ImageLoaded, Signed, Signature |
| 10 | Process access | Detects when one process opens a handle to another — key for LSASS credential dumping detection | SourceImage, TargetImage, GrantedAccess. Requires explicit config for TargetImage=lsass.exe — very noisy by default |
| 11 | File created | Did a process drop a file to disk — useful for detecting malware staging | TargetFilename, Image |
| 12/13 | Registry modified | Persistence via registry run keys and other registry-based mechanisms | TargetObject, Details |
| 22 | DNS query | What domains did a process look up — primary event for C2 beaconing and DNS exfiltration detection | Image, QueryName, QueryResults |

### Sysmon Detection Notes

**EventCode 1 vs EventCode 4688:** Both capture process creation but Sysmon EventCode 1 is significantly richer. It includes the full command line by default, file hashes for threat intelligence lookups, and the parent process image path. EventCode 4688 requires additional audit policy configuration and still provides less detail. Use Sysmon EventCode 1 as your primary process hunting event.

**EventCode 10 and LSASS:** Detecting credential dumping via LSASS memory access requires explicit Sysmon configuration targeting TargetImage=lsass.exe. Default and community Sysmon configs often exclude this rule because it generates significant noise. It must be added deliberately when tuning for credential dumping detection.

## 4. SPL Patterns and Field Notes

Common SPL patterns, field behaviors, and query building blocks that apply across multiple detection queries.

### Multivalue Fields

Several Windows Security events map multiple values to the same field name, which creates multivalue fields in Splunk. The most common example is Account_Name in account management events, which contains both the actor (who performed the action) and the target (which account was affected).

Use `mvindex()` to extract individual values by position:

```splunk
| eval Actor = mvindex(Account_Name, 0)
| eval Target = mvindex(Account_Name, 1)
```

This applies to EventCodes 4720, 4726, 4732, and 4625 among others. Without this extraction, table output will show both values stacked in the same cell, which makes the results difficult to read and impossible to filter correctly.

### Time Bucketing for Volume Analysis

Use `bucket` to group events into fixed time windows and count activity within each window. This is the foundation of brute force and anomaly detection:

```splunk
| bucket _time span=60s
| stats count by _time, user, host
| where count >= 5
```

### Coalesce for Field Name Inconsistencies

Different Windows machines sometimes use different field names for the same concept. Domain Controllers may log events with a `Computer` field while workstations use `host`. Use `coalesce()` to handle this gracefully:

```splunk
| eval Machine = coalesce(Computer, host)
```

### Distinct Count for Lateral Movement Detection

`dc()` counts the number of distinct values in a group. Using `dc(host)` per account reveals accounts that authenticated to multiple machines, which is a lateral movement indicator:

```splunk
| stats dc(host) as machines_accessed, values(host) as host_list by Account_Name
| where machines_accessed > 1
```

### Relative Time for Post-Attack Verification

After running an attack simulation, use relative time to scope your search to just the last few minutes rather than searching all historical data:

```splunk
| where _time >= relative_time(now(), "-5m")
```

## 5. MITRE ATT&CK Detection Mapping

Quick reference mapping MITRE ATT&CK techniques to the detection events and SPL queries used in this lab.

| Technique ID | Name | Tactic | Primary Detection Event | Key Indicator |
|---|---|---|---|---|
| T1059.001 | PowerShell Execution | Execution | Sysmon EventCode 1, EventCode 4688 | CommandLine containing -enc, -nop, bypass, or IEX flags |
| T1110.001 | Brute Force | Credential Access | EventCode 4625 | 5+ failures in 60 seconds from same source; Sub_Status 0xC0000064 or 0xC000006A |
| T1136.001 | Create Local Account | Persistence | EventCode 4720 + 4732 | New account creation followed by addition to Administrators group |
| T1558.003 | Kerberoasting | Credential Access | EventCode 4769 | Ticket_Encryption_Type=0x17 (RC4) on service ticket requests |
| T1021.002 | SMB Lateral Movement | Lateral Movement | EventCode 4624 | Logon_Type=3 from unexpected source; same account accessing multiple machines |
| T1053.005 | Scheduled Task | Persistence | EventCode 4698 | Unexpected task names or tasks created outside maintenance windows |
| T1078 | AD Enumeration (BloodHound) | Discovery | EventCode 4624 | Mass Logon_Type=3 events on DC01 from a single account in a short window |
| T1003.001 | LSASS Memory Dump | Credential Access | Sysmon EventCode 10 | TargetImage=lsass.exe with suspicious GrantedAccess values. Requires advanced Sysmon config |
| T1048.003 | DNS Exfiltration | Exfiltration | Sysmon EventCode 22 | Unusually long DNS query names, high query volume from a single process |

## 6. Audit Policy Requirements

Windows does not log most security-relevant events by default. This table documents which audit policy settings are required before each Event ID will appear in your SIEM.

| Event ID | Required Audit Policy | GPO Path |
|---|---|---|
| 4624, 4625, 4648 | Logon/Logoff: Audit Logon | Advanced Audit Policy > Logon/Logoff > Audit Logon |
| 4672 | Logon/Logoff: Audit Special Logon | Advanced Audit Policy > Logon/Logoff > Audit Special Logon |
| 4688 | Detailed Tracking: Audit Process Creation | Advanced Audit Policy > Detailed Tracking > Audit Process Creation |
| 4698 | Object Access: Other Object Access Events | Advanced Audit Policy > Object Access > Audit Other Object Access Events |
| 4720, 4726, 4732 | Account Management: Audit User Account Management | Advanced Audit Policy > Account Management > Audit User Account Management |
| 4768, 4769, 4771 | Account Logon: Audit Kerberos Service Ticket Operations | Advanced Audit Policy > Account Logon > Audit Kerberos Service Ticket Operations |
| 4776 | Account Logon: Audit Credential Validation | Advanced Audit Policy > Account Logon > Audit Credential Validation |
| 7045 | System: Audit Security System Extension | Advanced Audit Policy > System > Audit Security System Extension |

### Applying Audit Policy via GPO

All audit policies in this lab are applied via the Default Domain Policy GPO on DC01, ensuring consistent coverage across all domain-joined machines.

GPO path: `Computer Configuration > Policies > Windows Settings > Security Settings > Advanced Audit Policy Configuration`

After modifying any GPO, force an update on target machines:

```cmd
gpupdate /force
```

Allow a few minutes for Splunk to begin receiving the newly enabled event types. If events still do not appear, verify the forwarder inputs.conf includes the relevant log channel and that the forwarder service has read permission on the Security event log.
